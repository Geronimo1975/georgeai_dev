# georgeai.dev site rebuild: one repo-owned static site

Date: 2026-09-11
Status: approved in conversation, awaiting written review
Branch: `worktree-site-rebuild` (git worktree, isolated from the parallel session on `trust-and-positioning-remediation`)

## 1. Why

The site today is two systems glued together:

1. A single-page export from a design tool (`GeorgeAI.dc.html`, React + `support.js` template engine) that renders home, about, contact, services list, service detail, news, configurator and legal pages as client-side state. None of those pages has a URL of its own (except the `#contact` hash added today).
2. Twenty-four repo-owned static pages generated by `seo/generate_service_pages.py` (`/services/*`, `/work/*`, `/blog/*`, `/pricing/`).

Every positioning, legal, trust or accessibility fix to the export has to be re-applied as a string patch on each deploy (`seo/apply_content.py`, `seo/contact_page.py`, `brand/apply_brand.py`, `seo/head.html`, `seo/noscript.html`, `seo/inject_widget.py`: seven layers). The patches assert the export's exact shape and fail the deploy when it drifts. Defects found today that come straight from the export: pseudo-links, unbound form fields, a UTC off-by-one on booking dates, a crawlable footer block floating over page content at 900px, a header that overflows at phone widths, `unsafe-eval`/`unsafe-inline` required in the CSP.

Decision: retire the export. Every page becomes repo-owned HTML produced by one generator from JSON/Markdown content and Jinja2 templates. The design tool stops being a source.

## 2. Decisions taken (with the user, 2026-09-11)

| Question | Decision |
|---|---|
| Scope | The whole site, one system. |
| Languages | German and English as separate URL trees. FR/RO/AR dropped until there is demand. |
| Interactive features kept | Booking on contact (mailto + fallback), service configurator, light/dark theme, auth modal (`auth.js` + Django `/api/auth/*`). |
| Visual identity | Kept as shipped: colors, logo, contact data, the hero's motion and service panels. `DESIGN.md` is the token source. No redesign of direction; Impeccable is used for execution quality. |
| Technology | Python static generator (Jinja2), vanilla JS, nginx unchanged. Not Django server-side, not Astro. |
| URL scheme | `/` is German, `/en/` is English, 301s for the current English URLs. |
| Isolation | Git worktree on a new branch; integrate via PR. |

## 3. Repository layout

    legal/imprint.md  privacy.md  terms.md  cookies.md

  base.html                  <head> (meta, hreflang, JSON-LD slot, self-hosted fonts), skip link, header, footer, cookie banner
  pages/                     home, about, contact, services-hub, service, work-hub, work, blog-hub, post, pricing, configurator, legal
  partials/                  header, footer, hero, steps, service-card, work-card, testimonial, faq, cta-band, booking-form, configurator, cookie-banner

Retired after cutover (section 9): `exports/`, `seo/apply_content.py`, `seo/contact_page.py`, `seo/inject_widget.py`, `seo/head.html`, `seo/noscript.html`, `brand/apply_brand.py`, `seo/generate_service_pages.py` (its JSON-LD, sitemap and slug code moves into `build.py`), `site/support.js`, the vendored React.

Kept as is: `backend/` (Django serves `frontend/template/` verbatim and `/api/auth/*`), `backend/assets/auth.js` (gets stable field ids to hook instead of positional matching), `deploy/nginx.conf` and `deploy/docker-compose.yml` (edited only for 301s, CSP and web root), `DESIGN.md`, `PRODUCT.md`.

New dependency: `jinja2` (pip). Nothing else. `python3 -m pip install jinja2` is added to the deploy prerequisites.

## 4. URLs, languages, routing

German at the root, English under `/en/`. Service and project slugs are identical in both languages; only the section segment is translated.

| Page | DE | EN |
|---|---|---|
| Home | `/` | `/en/` |
| Services hub | `/leistungen/` | `/en/services/` |
| Service | `/leistungen/<slug>/` | `/en/services/<slug>/` |
| Work hub | `/projekte/` | `/en/work/` |
| Project | `/projekte/<slug>/` | `/en/work/<slug>/` |
| Blog hub | `/blog/` | `/en/blog/` |
| Post | `/blog/<slug>/` (only if written in DE) | `/en/blog/<slug>/` |
| Pricing | `/preise/` | `/en/pricing/` |
| Contact | `/kontakt/` | `/en/contact/` |
| About | `/ueber-mich/` | `/en/about/` |
| Configurator | `/konfigurator/` | `/en/configurator/` |
| Legal | `/impressum/` `/datenschutz/` `/agb/` `/cookies/` | `/en/legal/imprint/` `/en/legal/privacy/` `/en/legal/terms/` `/en/legal/cookies/` |

Rules:

- Every page carries `<link rel="alternate" hreflang="de|en">` to its pair and `hreflang="x-default"` to the German page. A post without a translation points only at itself.
- `<html lang="de">` / `lang="en"`. No RTL support (Arabic dropped).
- The header language switch links to the equivalent page, computed at build time. It never links to the home page unless the current page has no pair.
- Contact is a real page; the `#contact` hash from the SPA is gone. Legacy `/#contact` needs no redirect (hash never reaches the server).
- Trailing-slash directory URLs (`<path>/index.html`), matching the current nginx `index index.html;` setup.

301 redirects in `deploy/nginx.conf`, one `location` block each, permanent:

```
/services/(.*)  -> /en/services/$1
/work/(.*)      -> /en/work/$1
/blog/(.*)      -> /en/blog/$1
/pricing/       -> /en/pricing/
/about/         -> /en/about/
```

`/services/`, `/work/`, `/blog/` hubs are covered by the same patterns with an empty capture. Nothing currently in `sitemap.xml` may 404 after cutover; test 6.2 enforces it.

`build.py` regenerates `sitemap.xml` (both languages, `<xhtml:link>` alternates), `robots.txt` and `llms.txt` from the page inventory.

Translation workflow: German drafts are written by the assistant and marked `"_status": "draft"` (JSON) or `status: draft` (front-matter). `build.py` prints the count of draft pages per language at the end of every build so nothing unreviewed is forgotten. Legal texts (Datenschutz, AGB) are produced as structure with placeholders for the clauses that depend on legal advice; they are never invented and stay `draft` until the user or a lawyer clears them.

Copy rules (from `PRODUCT.md` and Impeccable): no em dashes; anchored in the missed-call pain, not in AI capability; only claims the site can back (8+ years, 40+ projects, five languages spoken, pilot in about two weeks, reply usually within two days, free 30-minute call); no new promises; every element that looks clickable navigates.

Structured data per page type: `Organization` + `Person` (site-wide, in `base.html`), `Service` (service pages), `CreativeWork` (projects), `Article` (posts), `FAQPage` (any page with an FAQ block), `BreadcrumbList` (all pages below a hub), `ContactPage` (contact).

## 6. Design system and components

Tokens: `DESIGN.md` values become CSS custom properties in `assets/site.css`, verbatim (`--canvas`, `--surface`, `--card`, `--cardBorder`, `--ink`, `--accent`, `--accentBtn`, `--body`, `--muted`, `--hairline`, `--navBg`, `--pillBg`, `--footerBg`, `--footerText`, `--footerHead`, `--gridline`). Light is the default set; dark is `html[data-theme="dark"]`, with `@media (prefers-color-scheme: dark)` as the fallback when no choice is stored. Fonts self-hosted: Newsreader (display, weight 400, negative tracking), Inter (body), JetBrains Mono (eyebrows and metadata only). No Google Fonts request, ever.

Layout: full-bleed sections with the existing `padX` gutters (56 / 28 / 20px), `sectionPadY` 88 / 56px; breakpoints `<860px` mobile and `<560px` narrow, expressed in CSS, not JS. No max-width wrapper unless a section needs one for line length (body copy capped at 65 to 75ch).

Components, each a Jinja partial plus a CSS block, no inline `style=""`:

- `header`: sticky, blurred `--navBg`, real `<a>` nav, language switch to the equivalent page, theme toggle, "Get in touch" button-link, hamburger with `aria-expanded` and Escape/outside-click close.
- `hero`: aurora, glow and rising-beam keyframes ported from the export's CSS; service panels as an accordion of `<button aria-pressed>`, keyboard operable, auto-rotating every 6s, paused on hover/focus, disabled under `prefers-reduced-motion`; eyebrow, `h1`, sub and two CTAs (`<a>`).
- `steps` (numbered list with hairlines), `service-card`, `work-card`, `testimonial` (rendered only when the language has entries), `faq` (`<details>`/`<summary>`, no JS), `cta-band`, `footer`.
- `booking-form`: the contact form rebuilt on 2026-09-11, ported one-to-one (labels, `aria-pressed` day and time chips, `<textarea>`, inline `role="alert"` validation, honest "press Send" confirmation with copy / re-open / WhatsApp fallbacks). The form is placed before the "Direct" column on mobile.
- `configurator`: services by category, scale, add-ons, live estimate text; submission by `mailto:` with everything selected in the body, same fallbacks as booking.
- `cookie-banner`: fixed at the bottom, never over form controls; shown only when `site.json` has an analytics id. "Essential only" / "Accept all", choice in `localStorage.ga_cookie`.
- Newsletter block: dropped until an endpoint exists (PRODUCT.md: no pseudo-forms).

Not carried over: the floating `seo:footer` link block (its links live in the real footer), the header overflow at phone widths, the "Bundled Page" snapshot, all `<span onClick>` controls.

Impeccable's role: each page type goes through `$impeccable shape` (a short brief the user confirms) before `$impeccable craft`; the finished set gets `$impeccable audit` (a11y, responsive, performance) and `$impeccable polish`. Direction is fixed by `DESIGN.md`; Impeccable works on execution.

Accessibility target: WCAG 2.2 AA. Skip link, one `h1` per page, landmark elements, visible `:focus-visible` on every control, contrast at least 4.5:1 for text in both themes, all interactive elements native (`<a>`, `<button>`, `<details>`), no `tabindex` above 0.

## 7. JavaScript

One file, `assets/site.js`, an ES module with no dependencies, roughly 400 lines. Each module initialises only when its root element is present.

| Module | Behaviour | State |
|---|---|---|
| `theme` | reads `localStorage.ga_theme`, else `prefers-color-scheme`; sets `data-theme` on `<html>` before first paint (inline bootstrap of a few lines in `base.html` to avoid a flash); header toggle | localStorage |
| `menu` | hamburger open/close, `aria-expanded`, Escape and outside click | DOM |
| `hero` | panel activation by click and keyboard, auto-rotate with pause, honours reduced motion | DOM |
| `booking` | logic of `seo/contact_page.py` ported: local date keys (no UTC shift), validation, `mailto:` handoff, copy / WhatsApp fallbacks, "change something" keeps values | DOM |
| `configurator` | selection state, estimate text from `<script type="application/json">` embedded at build time, `mailto:` handoff | DOM |
| `cookie` | banner, consent storage, loads analytics only after "Accept all" and only if an id is configured | localStorage |

Language switching needs no JS (build-time links). `auth.js` stays a separate file in `backend/assets/`, loaded as today; the login/signup modal markup in `base.html` gives its fields stable ids (`ga-auth-email`, `ga-auth-password`, `ga-auth-name`) so `auth.js` can hook by id instead of by position. `auth.js` keeps degrading gracefully when `/api/auth/*` is absent.

Without JavaScript every page is fully readable and navigable; forms show their fields plus a plain `mailto:` link.

Security: with no React, no Babel and no inline styles, `deploy/nginx.conf` moves the CSP from `Content-Security-Policy-Report-Only` to enforced `Content-Security-Policy` with `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self' mailto:; frame-ancestors 'none'`. The theme bootstrap script gets a nonce or moves to `site.js` with a `<meta>` fallback if the nonce plumbing is not worth it (decided during implementation; either is CSP-clean).

## 8. Build and verification

`build.py`:

1. Loads `content/site.json` and, per language, every JSON and Markdown file; validates required keys (a missing key fails the build with the file and key named).
2. Computes the page inventory (URL, language, template, content, pair URL) for both languages.
3. Renders each page with Jinja2 (`autoescape` on), writes `site/<path>/index.html`.
4. Copies `assets/` to `site/assets/`, `backend/assets/auth.js` to `site/auth.js`, favicons and the logo mark to `site/`.
5. Writes `sitemap.xml`, `robots.txt`, `llms.txt`.
6. Prints: pages built per language, draft pages per language, total time. Exit code non-zero on any validation error.

`tests/` (run by `deploy.sh` before rsync; `python3 -m pytest tests/`):

1. **Determinism**: build twice into temp dirs, byte-identical.
2. **URL inventory**: every `<loc>` in the last deployed `sitemap.xml` (fetched from the live site or a checked-in snapshot) either exists in the new build or matches a 301 pattern in `deploy/nginx.conf`. No URL lost.
3. **Playwright, every page, both themes, 1280px and 390px**: no horizontal overflow, no console errors, every internal link answers 200, reciprocal `hreflang`, exactly one `h1`, focus visible on the first interactive element, axe-core reports no serious or critical violations, text contrast at least 4.5:1.
4. **Flows**: booking (empty submit shows the alert; full submit reaches the confirmation with the chosen local date; fallbacks present), configurator (selection changes the estimate; submit builds the mail body), theme toggle persists across reload, mobile menu opens and closes by keyboard.
5. **Content**: no em dash in any rendered page, no `[TODO]` or `[placeholder]` in a non-draft page, no `onclick` attributes, no `style=""` attributes, no external font or script hosts.

Playwright is already installed globally (v1.63, Chromium/Firefox/WebKit downloaded on 2026-09-11); tests use Chromium.

## 9. Rollout

Each step is reversible on its own.

1. All work on `worktree-site-rebuild`. `main` and the parallel branch are untouched.
2. Local build plus green tests; the user reviews screenshots of every page type in both themes.
3. Deploy to the VPS into a parallel directory (`/opt/georgeai-next`) served by a second nginx container on a test hostname through Traefik (`next.georgeai.dev`, Let's Encrypt like the main host). The user checks it live, on a phone too.
4. Cutover: `nginx.conf` with the 301s and the enforced CSP, web root switched to the new directory, new `deploy.sh`. Rollback is switching the web root back; under a minute.
5. After one stable week: delete `exports/`, the patch scripts listed in section 3, `seo/vendor` (moved to `assets/`), the vendored React. `frontend/template/` keeps mirroring `site/` for Django.
