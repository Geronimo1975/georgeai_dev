# SEO layer for georgeai.dev

All SEO lives in `seo/` and is applied by `deploy.sh` on every deploy
(idempotent, runs even with `--no-content`). **Never edit SEO in `site/`** —
it is wiped and regenerated.

| File | What it is |
|------|------------|
| `seo/head.html` | title / meta / OG / JSON-LD block, injected before `</head>` (marker `seo:head`); deploy also sets `lang="en"` on `<html>` |
| `seo/generate_service_pages.py` | generates the `/services/` hub + one static page per service (data: `georgeai_services.json`), the `/blog/` hub from the HTML fragments in `blog/`, and regenerates `sitemap.xml` with every URL |
| `seo/apply_content.py` | re-applies `seo/hero.json` + `seo/testimonials.json` over the copy the export hard-codes (a re-export silently reverts positioning work) |
| `seo/inject_widget.py` | injects the lead-capture widget across all generated + static pages; runs last in the deploy |
| `seo/assets/` | repo-owned static assets copied into `site/assets/`. Currently `og-cover.jpg`, the 1200×630 / 137 KB social card |
| `seo/robots.txt` | crawler policy — AI answer-engine bots explicitly allowed |
| `seo/sitemap.xml` | regenerated by the page generator; copied into site/ |
| `seo/llms.txt` | AI-crawler guidance, copied into site/ |
| `seo/favicon.svg`, `seo/responsive.css` | copied into site/ |

Service names in `georgeai_services.json` must stay in sync with the
design-tool export.

## Workflow

1. Edit files in `seo/`.
2. Apply with `./deploy.sh --no-content` (re-injects every layer without
   unpacking a new export).
3. Verify (below).

```bash
curl -s https://georgeai.dev | grep -A2 'seo:head'
curl -sI https://georgeai.dev/robots.txt   # and /sitemap.xml, /llms.txt
curl -s https://georgeai.dev/ | grep -o '<meta property="og:image[^>]*>'
curl -sI https://georgeai.dev/assets/og-cover.jpg | head -3
```

## Gotchas

- **The homepage is a SPA.** Its served HTML carries ~520 unrendered `{{ }}`
  tokens and several placeholder `<h1>`s for the views that are not active.
  Most AI crawlers do not run JS, so anything that must be cited has to be
  server-rendered or live on a generated static page.
- **OG images must be small.** The export's `assets/SEO_AI.png` is 1.79 MB —
  over the size LinkedIn and WhatsApp will fetch, so shares rendered blank.
  That is why the card is repo-owned in `seo/assets/`. Keep any replacement
  1200×630 and well under 1 MB. (`SEO_AI.png` itself stays in the web root —
  the export uses it as the featured-project image.)
- Repo-owned assets go through `apply_seo`, *not* by editing `site/assets/`,
  which the export repopulates.

## Design context

`DESIGN-claude.md` — but read its "Production override" note: the frontmatter
describes the palette **as the export ships it** (Anthropic coral `#cc785c`),
which fails WCAG AA. The LIVE accent is `#ff8300` (dark) / `#c2410c` (light)
with `#141413` ink button labels, rewritten at deploy time by
`brand/apply_brand.py`. Never treat `#cc785c` as the site's colour.
