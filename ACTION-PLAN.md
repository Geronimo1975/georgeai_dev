# SEO Action Plan — georgeai.dev

Derived from `FULL-AUDIT-REPORT.md` (audit run 2026-08-26, score 70/100).
Ordered by priority. Every fix belongs in a repo-owned deploy layer — never in `site/`,
which is wiped on every deploy.

## Critical — fix immediately

### 1. Get real content into the homepage's crawlable HTML
**Problem:** 535 `{{ }}` placeholders and 10 `<h1>` in the raw HTML; AI crawlers and
Google's first pass see a skeleton.
**Fix:** extend the existing `<noscript>` block into a real pre-rendered fallback, or
prerender the homepage at deploy time (`seo/apply_content.py` already owns the hero
strings — it can emit the resolved copy into the static markup). At minimum, strip the
`{{ }}`-token `<h1>` elements down to one real `<h1>`.
**Effort:** M (½–1 day) · **Owner file:** `seo/apply_content.py`, `seo/noscript.html`

### 2. Publish `/impressum/`, `/about/`, `/contact/` as static pages
**Problem:** all three 404. Legal identity exists only inside the SPA.
**Fix:** add them under `pages/` so `apply_pages` copies them verbatim; source the
Impressum text from `seo/legal.json` (already the source of truth) and cite § 5 DDG.
**Effort:** S (2–3 h) · Also closes the § 5 DDG exposure before the Stripe go-live.

### 3. Cut 5.5 MB of image weight
**Problem:** 7.8 MB homepage; three PNGs are 5.7 MB of it.
**Fix:** convert `concept_smart_home.png`, `SEO_AI.png`, `medical_ai.png` to AVIF (WebP
fallback) at display width; serve via `<picture>`/`srcset`. Add long `max-age=31536000,
immutable` cache headers for `/assets/*` in `deploy/nginx.conf`.
**Effort:** S (2–3 h) · **Impact:** ~70 % page-weight reduction

### 4. Fix the `{{ detail.img }}` 404
**Problem:** every page load requests `https://georgeai.dev/%7B%7B%20detail.img%20%7D%7D`.
**Fix:** the binding added by `images/apply_images.py` is emitted before the template
resolves — guard the `<img>` with the same `v-if`/render condition the surrounding block
uses, or bind `:src`.
**Effort:** S (1 h)

## High — within one week

### 5. Deepen the 15 service pages from 140 → 700+ words
Each needs unique substance: a concrete problem narrative, a worked example with real
numbers, what the client provides, timeline, pricing anchor linking to `/pricing/`, and
2–3 FAQs with `FAQPage` schema. Generated by `seo/generate_service_pages.py` from
`georgeai_services.json` — extend the JSON schema with the new fields rather than
hand-editing output.
**Effort:** L (2–3 days for all 15) · **Impact:** highest single ranking lever

### 6. Rewrite the 13 short titles
`CRM — GeorgeAI` → `Custom CRM Development for SMBs — Django & n8n | GeorgeAI`.
Target 50–60 chars, lead with the service + a qualifier. Same file as #5.
**Effort:** S (2 h)

### 7. Build hub-and-spoke internal linking
Each service page should link to 3–4 related services and to any blog post covering the
topic; each blog post should link to the services it implies. Add a "Related services"
block to the service-page template.
**Effort:** M (½ day)

### 8. Add `hreflang`
The site serves en/de/fr/ro/ar behind client-side switching at one URL — only English is
indexable. Either generate per-language URL paths (`/de/`, `/fr/`…) with reciprocal
`hreflang` + `x-default`, or drop the multilingual claim from the schema's
`knowsLanguage`. The first is worth real German traffic given the target market.
**Effort:** L (2–3 days) · Largest untapped opportunity

## Medium — within one month

### 9. Expand `sameAs`
Add LinkedIn and every profile, directory listing and publication. `sameAs` is the primary
entity-resolution signal for both the Knowledge Graph and LLM brand recall.
**Effort:** S (1 h) · **File:** `seo/head.html`

### 10. Add `Offer`/`price` to service schema
`/pricing/` publishes fixed prices but the individual `Service` nodes carry none. Link
each `Service` to its `Offer`.
**Effort:** S (2 h)

### 11. Real `lastmod` per URL
Every sitemap entry currently shares today's date. Derive from the blog post `date` meta
and from source-file mtimes.
**Effort:** S (2 h) · **File:** `seo/generate_service_pages.py`

### 12. Publish 2–4 more blog posts
The existing two are the site's best assets and its only AI-citable content. Target the
questions the service pages imply: "What does an AI phone agent cost in Germany?",
"n8n vs Zapier for a 10-person company", "RAG on your own documents — what it actually
takes".
**Effort:** L (1 day each) · Also the only realistic lever on off-site brand mentions

### 13. Unify the font strategy
The homepage self-hosts; service pages fetch Google Fonts cross-origin. Pick self-hosting
and subset — 31 `@font-face` rules for a 5-language site is more than the critical path
needs.
**Effort:** M (½ day)

### 14. Add case studies with named numbers
No page currently contains a client outcome. Two or three short case studies would carry
more E-E-A-T weight than any other content type available here.
**Effort:** L

## Low — backlog

- Trim the two over-length blog titles (98 and 73 chars) to ≤ 60.

- Add `speakable` schema to the blog posts.
